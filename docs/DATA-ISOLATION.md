# 数据隔离与配置边界

## 每套安装使用自己的数据

Compose 为每套安装创建独立项目名、MySQL 服务、数据库卷和附件卷。应用连接当前 Compose 网络内的数据库 `db`，数据库端口默认不暴露到宿主机。安装工具随机生成数据库密码和应用主密钥，不复制维护者站点的连接配置。

源码包含 SQL 建表迁移以及默认会员档位、充值模板等初始值，不包含用户、邮件、订单、积分流水、邮箱授权、生产日志或数据库备份。新装管理员由安装者通过一次性命令创建，没有内置管理员账户。

## 配置不随版本同步

管理员修改价格、公告、账号和第三方配置，写入的是当前安装的数据库。发布新代码不会读取并导出这些值，其他安装也不会接收这些值。升级保留本地 `.env`、数据库、附件和 TLS 文件。

`.gitignore` 可防止常见的误提交，但不能保护被人为强制提交的文件；不要上传自己的 `.env`、数据库导出或真实邮件作问题示例。切勿把完整服务器目录打包成源码 Release。

## 程序会连接哪些外部服务

- 更新检查默认读取维护者的公开版本公告，只携带常规请求头及程序版本标识，不携带账号、邮件、订单、密钥或数据库内容。这不是业务数据同步接口。
- 启用中继、OAuth、验证码、Telegram 或支付后，会按各模块用途访问对应服务商。这些接入由安装者自行配置；例如中继程序会读取安装者授权的上游邮箱。
- NodeMail 的管理员可访问本机管理权限范围内的数据。自行部署不等于自动消除运维、主机或依赖风险。

## 密钥与数据清理

`GUEST_SESSION_SECRET` 还参与应用配置和密钥加密，必须保留，不能把更换它当作普通更新步骤。安装工具会拒绝主密钥不匹配的启动或升级。

邮箱到期和日志保留仍按当前后台设置运行；独立部署不意味着无限保留。中继远端清理的具体动作以后台配置与服务商语义为准，不要将移入垃圾箱描述为永久删除。
