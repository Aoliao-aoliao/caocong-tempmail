# 第三方账号接入

支付商户、充值档位、回调地址与到账排查，请看独立的 [支付与充值配置](/payments.html)。

除了人机验证和发信邮箱，其他服务都可以等基本收信正常后再接。安装包不提供作者的应用、机器人或支付商户，也不会因为用了同一份源码就共用作者的账户。

## 选你要接的服务

| 服务 | 用来做什么 | 逐步教程 |
| --- | --- | --- |
| Cloudflare Turnstile | 注册、找回密码、访客申请时的人机验证，**必配** | [人机验证](/turnstile.html) |
| 发信邮箱 | 给用户发找回密码验证码 | [找回密码](/password-mail.html) |
| Gmail / Outlook | 中继收信，让用户使用主流邮箱后缀 | [中继邮箱](/relay-setup.html) |
| NodeLoc 登录 | 用户用 NodeLoc 账号登录或绑定 | [NodeLoc 登录与绑定](/nodeloc-login.html) |
| Telegram | 用户绑定 Telegram 账号（暂不推送） | [Telegram 绑定](/telegram.html) |
| NodeLoc 能量 / USDT | 用户充值积分 | [支付与充值配置](/payments.html) |

::: tip 推荐顺序
人机验证 → 发信邮箱 → 收信（自有域名或中继）→ 支付 → NodeLoc 登录 / Telegram。前两项不配，用户就无法注册和找回密码。
:::

## 支付与积分

先在自己的服务商处取得商户信息，再按后台字段填写。核对商户属于自己、回调地址指向自己的网站、币种和价格符合自己的设置。

USDT 网关需要在安装目录 `.env` 显式配置自己的 `NODEMAIL_GMPAY_ORIGIN`，填 HTTPS 根地址，再按安装流程启动应用并填写后台商户凭据。留空时不能启用这个网关。相关参数见 [安装指南](/installation.html)。

已经产生订单后，不要只改网关域名就切换支付平台，旧订单的查询和通知仍需要正确处理。切换需单独安排旧订单的处置。

### 怎样验收？

先确认服务商是否提供测试环境；使用测试环境核对下单、取消、通知和本站订单状态。只有账户所有者确认后再安排真实小额测试。网页跳回成功页不等于服务端已经确认付款。

订单、积分流水与业务防重复记录共同承担业务核对。不要清表测试重复回调，也不要手工把订单改成已支付来代替完整验收。

## 密钥更换前先备份

安装时生成的 `GUEST_SESSION_SECRET` 还用于保护多类服务凭据。它不是可以随手换掉的临时密码；更换或丢失后，原有加密资料可能无法读取。

请保留原 `.env`，按 [备份说明](/backup.html) 与数据库一起保存。服务商主动轮换凭据时，更新对应后台字段即可，不要重新生成整份安装配置。
