# 第一次进入后台

安装成功后，打开 `https://你的域名/user/login.cgi`。用安装时创建的邮箱和密码登录，再进入 `https://你的域名/admin/`。

首次配置建议按这页顺序做。先验证登录和收信，再开放注册与付费功能，出错时也容易判断是哪一步的问题。

## 1. 确认管理员能正常使用

打开后台首页、系统配置和用户页面，刷新后仍保持登录。如果不停跳回登录页，先检查 HTTPS 和代理头，不要反复重建管理员。

安装工具只能在账户表为空时创建初始管理员，不是忘记密码后的重置工具。

## 2. 配置注册需要的验证码

进入后台的 **人机验证** 页，填写自己 Cloudflare Turnstile 的密钥，逐步说明见 [人机验证](/turnstile.html)。找回密码还需要配置发信邮箱，见 [找回密码](/password-mail.html)。创建验证码站点时使用实际访问域名。注册依赖验证码，不能因为登录页能打开就认为新用户一定能完成注册。

保存后，用未登录的浏览器窗口打开注册页面，确认验证码能加载。不要把 Secret Key 发给用户，也不要放进公开截图。

## 3. 选择收信方式

后台“域名”用于管理自己的收信域名；“中继”用于管理接入的上游邮箱。选择一种先完成测试，具体见 [域名与收信](/mail.html)。

使用自己的测试邮箱申请一个收件箱，再从自己控制的外部邮箱发一封普通文字邮件。确认收到了以后，再测试小附件。测试邮件不要放真实用户数据。

## 4. 检查邮箱期限和申请档位

系统配置中的邮箱生命周期、申请档位决定用户能申请什么邮箱、能保留多久。先看清当前值，再根据自己的服务方式修改。

不要把临时邮箱当长期归档服务。系统会按配置执行到期清理；如果准备向用户承诺长期保存，需要先核对实际有效期及清理策略，并做好备份。

## 5. 再配置会员和付款

检查会员档位、积分和充值价格。新装自带的是可调整的默认模板，并不代表支付渠道可用。

只有确认商户、回调和订单流程都属于自己的环境，才开放对应付款入口。不要只看到“支付成功”的跳转页就判断到账，以本站订单状态和积分流水为准。

## 后台这几类记录有什么区别？

| 页面或记录 | 用途 |
| --- | --- |
| 订单 | 查看付款渠道、金额和订单状态 |
| 积分流水 | 核对用户积分的增加与扣减 |
| 审计日志 | 排查操作行为、时间和结果 |
| 业务防重复凭据 | 防止同一笔业务被重复处理，内部独立保存 |

当前审计日志保留界面默认显示 30 天，并支持设置保留期限。清理审计日志不会代替订单或积分数据管理；自动清理是否已启用，以后台状态为准。不要通过直接删数据库表的方式“清理日志”。

## 开放给用户前自己走一遍

用一个普通测试账户完成注册、申请邮箱、收信、查看附件和退出登录。普通账户应看不到管理员页面。付费功能如果暂时没准备好，先保持关闭即可。

每个后台菜单的详细说明见 [后台功能说明](/admin-guide.html)；可以转给用户的操作说明见 [用户使用指南](/user-guide.html)。具体第三方功能见 [第三方账号接入](/integrations.html)。日志和数据的备份范围见 [备份自己的数据](/backup.html)。
