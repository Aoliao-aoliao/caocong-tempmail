# USDT：对接自己的收款网关

这篇对应后台 **充值配置 → USDT 支付**。当前临时邮箱通过 **GM Pay / EPUSDT v2** 网关建单和核验，支付资产固定为 **TRON 主网 USDT / TRC20**。

它不是把钱包地址直接填进临时邮箱，也不是通用易支付的 `/submit.php` 接入。你需要先有一个接口兼容的收款网关，由网关管理收款钱包、监听链上交易，再通知临时邮箱发积分。

## 1. 先把三部分分清

| 部分 | 负责什么 | 需要在哪配置 |
| --- | --- | --- |
| 临时邮箱 | 充值档位、订单、积分和到账核验 | 本项目后台 |
| 收款网关 | 返回收银台、地址、准确金额，识别链上到账 | 你自己的 GM Pay / EPUSDT 网关 |
| 钱包 | 保存对应网络的资产 | 你控制的钱包及网关的收款配置 |

临时邮箱只需要网关商户 PID 和 API 密钥，不需要钱包助记词或钱包私钥。不要把这些钱包资料填到 `secret_key`。

## 2. 从网关取得什么？

登录你自己的网关后台，在商户或 API 配置中取得 **PID** 与 **secret_key**，并确认网关已配置 TRON 主网 USDT 收款。网关版本不同，菜单名可能不同；这里不把未实测过的菜单写成固定按钮。

同时记下网关对外的 HTTPS 根地址，例如 `https://pay.example.com`。这三项必须属于同一个网关、同一个商户。

| 你手里的信息 | 可以用吗？ |
| --- | --- |
| 兼容本页接口的 GM Pay / EPUSDT v2 PID、secret_key | 按下面步骤配置 |
| 普通易支付平台的 PID、MD5 密钥或 RSA 私钥 | 不能直接当作此网关凭据 |
| TronLink / 欧易等钱包的收款地址 | 应配置在网关收款侧，不是本站商户 PID |
| 网关支持多链 | 本站这一条适配仍只请求 TRON USDT |

## 3. 在安装目录配置网关地址

在 1Panel 文件管理中打开原安装目录的 `installer/.env`，找到：

```dotenv
NODEMAIL_GMPAY_ORIGIN=
```

在等号后填写自己的网关根地址，例如：

```dotenv
NODEMAIL_GMPAY_ORIGIN=https://pay.example.com
```

不要添加 `/submit.php`、`/api`、管理后台路径或密钥参数。保存时保留文件原有权限和其他内容，尤其不要改变数据库密码及 `GUEST_SESSION_SECRET`。

在**原 installer 目录**执行下面命令，使容器读取配置：

```bash
node manage.mjs start
```

不重新执行 `configure` 或 `init`。启动成功后，再进后台填写商户信息。

## 4. 配置充值档位与商户

先在 **充值配置 → 充值档位** 填写积分和美元价格。后台价格单位是**美分**：`100` 表示 `1.00 USD`，不是 100 美元。每档改完单独保存并启用。

然后切换 **USDT 支付**：

| 字段 | 填什么 |
| --- | --- |
| 商户 PID | 网关提供的商户标识 |
| API 密钥 secret_key | 同一商户的 API 密钥，完整复制，不多加引号或换行 |
| 启用 USDT 支付 | 准备完毕后打开并保存 |

当前代码要求 PID 为字母、数字或下划线，长度 1–64；密钥长度 16–1024 且不能含换行。若网关给出的格式不符合，不要自行截短或改写，先确认接口版本是否兼容。

同一商户留空密钥表示保留原值；换 PID 必须同时填写对应密钥。保存后页面应显示正确网关和启用状态，密钥不会原文回显。

## 5. 核对本站回调

展开 **回调地址与支付说明**，复制后台显示的地址。自己的域名应与安装时配置的站点根地址对应。

```text
到账通知：https://你的邮箱域名/api/payment/gmpay-notify
付款返回：https://你的邮箱域名/api/payment/gmpay-return
```

演示站根地址为 `https://nodemail.513399.xyz`，但安装者的通知必须回到自己的域名。代码在每笔建单请求中传入通知和返回地址；若网关要求配置通知白名单，按自己的网关规则登记。

通知地址不要被验证码挑战、额外的登录认证或缓存挡住。保留接口自身的签名核验，不要为了“让回调通过”关闭验签。

## 6. 对照你的网关是否兼容

当前代码实际调用：

```text
POST /payments/gmpay/v1/order/create-transaction
GET  /pay/checkout-counter-resp/<trade_id>
```

建单请求是 JSON，主要字段如下。这些由程序自动生成，不需要在后台逐项录入：

| 字段 | 内容 |
| --- | --- |
| `pid` | 已保存的网关商户标识 |
| `order_id` | 本站订单号 |
| `currency` | `usd` |
| `token` | `usdt` |
| `network` | `tron` |
| `amount` | 档位的美分价格 ÷ 100 |
| `notify_url` | 本站 gmpay-notify 路径 |
| `redirect_url` | 本站 gmpay-return 路径 |
| `signature` | 使用 secret_key 生成的 HMAC-SHA256 签名 |

成功响应需符合当前实现读取的结构：`status_code` 为 `200`，并包含 `data`。收银台链接必须属于配置的网关，路径为 `/pay/checkout-counter/<trade_id>`。接口名称相似但签名、字段或返回结构不同，仍需要专门适配。

## 7. 用户到底要付多少？

本站向网关传档位 USD 价格。网关返回的 `actual_amount` 才是用户需要支付的准确 USDT 数量；网关还可能有自身的汇率或金额区分规则。

因此用户应按**当前收银台**显示的网络、地址、金额和有效期付款。不要用“1 美元一定转 1 USDT”的口头说明覆盖收银台结果，不要手工四舍五入，也不要重复使用上一笔订单信息。

## 8. 验收与故障排查

先用自己的账户创建一笔测试订单，核对跳转到的是自己的网关，链是 TRON，资产是 USDT，金额与档位一致。真实付款由站点所有者确认后进行；本文操作不会代替你发起付款。

付款后检查本站订单、积分与流水。再次刷新、返回和查询同一订单，积分只应发放一次。还应检查未付款或过期订单没有积分增加。

| 现象 | 先查哪里 |
| --- | --- |
| 页面显示网关未配置 | `.env` 的 NODEMAIL_GMPAY_ORIGIN 及容器是否重新读取 |
| 凭据已保存但无入口 | 支付开关、充值档位开关，以及保存结果 |
| 创建订单超时 | 本站服务器能否连接网关，网关是否正常返回 |
| 返回格式或收银台地址无效 | 网关接口版本、返回字段及地址是否符合上一节 |
| 链上已到账，本站没积分 | 网关是否确认交易、通知投递记录、本地原订单核验结果 |
| 金额、币种或网络不匹配 | 当前订单的 amount、actual_amount、资产、链和交易是否一致 |

已付款但未到账时保留原订单号、交易号和时间，查询原订单。不要让用户重复转账，也不要把数据库订单强制改为已支付。更换网关或凭据前，先处理未结算订单并保留旧凭据所需的恢复资料。
