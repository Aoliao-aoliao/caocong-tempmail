# 准备服务器与域名

先确认下面几件事，再开始安装。这样不会做到一半才发现服务器不能收邮件，或域名不在自己手里。

## 一台能运行 Docker 的 Linux 服务器

需要 Docker Engine、Compose v2 和 Node.js 22.12 或更新版本。Compose 需要支持 `up --wait`。服务器能下载基础镜像和 npm 依赖，否则第一次构建会失败。

项目还没有给出经过压测的最低配置，不能只按“多少核、多少内存”保证能跑多少用户。首次构建、MySQL、邮件及附件都要占空间，建议先在没有其他重要业务的新环境验收。

在服务器终端执行：

```bash
docker info
docker compose version
node --version
df -h /opt
```

前三条确认工具可用，最后一条查看准备存放项目的分区还剩多少空间。有 1Panel 不代表主机上已经装了 Node.js，容器内的 Node.js 运行环境也不能代替安装工具所需的主机命令。

## 一个可以改解析的域名

这里用 `example.com` 举例：

| 名称 | 用来做什么 |
| --- | --- |
| `mail.example.com` | 用户访问网页和后台 |
| `mx.example.com` | 其他邮件服务器投递邮件时连接的地址 |
| `example.com` | 邮箱的后缀，如 `hello@example.com` |

三个名字有不同用途。网页用的 A 记录配好了，并不代表收信需要的 MX 也配好了。

如果这个域名已经在使用企业邮箱，不要覆盖原有 MX。先使用一个专门的子域名做 草丛临时邮箱 收信，例如 `inbox.example.com`，相应邮箱就是 `hello@inbox.example.com`。

## 先决定怎样收信

**自有域名收信：** 需要服务器允许入站 TCP 25。到云厂商控制台确认安全组、系统防火墙和平台政策。只开放服务器防火墙，无法解除云厂商层面的限制。

**中继收信：** 使用自己有权接入的上游邮箱，按其认证方式配置 IMAP 或 OAuth。不是输入任意邮箱地址就能接收它的邮件，也不要把普通邮箱密码当成所有服务商通用的 IMAP 密码。

## 端口怎么留？

| 端口 | 谁会访问 | 处理方式 |
| --- | --- | --- |
| 80、443 | 访问网页的用户 | 由网站代理监听，安全组允许访问 |
| 4321 | 同机网站代理 | 默认仅监听 127.0.0.1，不需要对公网开放 |
| 25 | 外部邮件服务器 | 自有域名收信需要允许入站 |
| 3306 | 应用容器 | 数据库只在内部网络，无需映射公网端口 |
| SSH、1Panel 端口 | 你自己 | 保留现有管理入口，按自己的管理网络限制来源 |

## 开始之前留好这些信息

准备网站域名、收信域名、管理员登录邮箱。管理员邮箱建议用自己已有、能收信的地址，密码至少 12 位。

不用提前手工建数据库，不用寻找默认密码，也不用购买支付服务才能装站。先完成 [1Panel 安装](/panel.html)，确认能登录后再接其他功能。
