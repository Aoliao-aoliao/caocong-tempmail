# NodeLoc 能量支付：从应用到到账

这篇对应后台 **充值配置 → NodeLoc 支付**。用户付 NodeLoc 能量，本站发积分；它不是 USDT，也不使用“NodeLoc 登录”那组 Client ID 和 Client Secret。

下面按实际接入顺序操作。演示站是 `https://nodemail.513399.xyz/`；自己部署时，所有本站地址都换成你的域名。

## 1. 先准备支付应用

登录自己的 NodeLoc 账号，进入 [支付应用管理](https://www.nodeloc.com/payment/applications)，创建或选择用于本站的支付应用，按平台提示完成审批。不同平台页面版本的按钮可能变化，以实际页面为准。

需要取得三项资料：**支付商户 ID、应用登记的商户公钥、NodeLoc 平台公钥**。本站持有与商户公钥配对的商户私钥。

| 资料 | 放在哪里 | 用途 |
| --- | --- | --- |
| 商户 ID / pid | 本站 NodeLoc 支付分区 | 标识你的支付应用 |
| 商户公钥 | NodeLoc 对应支付应用 | 平台校验本站发出的支付请求 |
| 商户私钥 | 本站“商户 RSA 私钥” | 本站签名请求，不能放到公开页面 |
| NodeLoc 平台公钥 | 本站“NodeLoc 平台 RSA 公钥” | 本站校验平台返回和付款通知 |

**商户公钥与平台公钥不是同一把钥匙。** 这是签名配置最容易填反的地方。

## 2. 没有商户密钥时怎样生成？

如果支付应用已有正在使用的商户公钥，先找回配套私钥，不要直接覆盖，否则可能影响同一个应用的其他接入。

为全新支付应用生成密钥时，可在自己可信的 Linux 服务器终端运行下面的命令。需要已安装 OpenSSL；不要使用随机在线密钥生成网站。

```bash
mkdir -m 700 ~/nodeloc-payment-keys
cd ~/nodeloc-payment-keys
umask 077
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out merchant-private.pem
openssl pkey -in merchant-private.pem -pubout -out merchant-public.pem
```

使用文件编辑器读取文件：把 `merchant-public.pem` 的完整内容登记到 NodeLoc 支付应用；把 `merchant-private.pem` 的完整内容填入本站私钥字段。包含 `BEGIN` / `END` 首尾行，保留换行。不要把私钥截图发出来。

这里的目录应是新建的专用目录。若提示已经存在，先检查原文件，不要照着命令覆盖。当前代码要求 RSA 至少 2048 位。

## 3. 配置平台汇率

在 NodeLoc 的该支付应用中，将汇率设置为 **1 单位货币 = 1 能量**。本站按档位的能量价格构造支付金额，不会替你修改平台的汇率。

例如某档收取 20 能量，本站请求的 `money` 是 `20.00`。如果平台仍按 100 倍换算，就会出现与预期不同的金额。必须先在平台完成设置，再勾选本站的汇率确认。

## 4. 填写临时邮箱后台

用超级管理员登录自己的站点，打开 `/admin/commerce.cgi`，切到 **NodeLoc 支付**。

| 本站字段 | 实际填什么 | 怎么确认 |
| --- | --- | --- |
| 商户 ID（易支付 pid） | 当前 NodeLoc 支付应用的数字 ID | 不是 OAuth Client ID，也不是其他易支付站的 PID |
| 本站 HTTPS 根地址 | `https://你的邮箱域名` | 不带 `/admin`、查询参数或登录路径 |
| 商户 RSA 私钥 | 上一步配对的商户私钥全文 | 平台登记的是它对应的公钥 |
| NodeLoc 平台 RSA 公钥 | 从平台取得的平台公钥全文 | 不要填商户公钥 |
| 汇率确认 | 核对平台已设为 1 后勾选 | 只勾选不会改变平台汇率 |

演示站对应的本站根地址是 `https://nodemail.513399.xyz`。安装者不要照填演示域名。

同一商户编辑其他设置时，私钥留空会保留原密钥。换商户 ID 则必须重新填写新商户配套私钥。保存后不回显密钥属于正常行为。

## 5. 设置售价并开启

先到“充值档位”保存积分数量，然后回到 NodeLoc 支付页，为需要出售的档位填写整数能量价格。`0` 表示不通过这条渠道出售；至少一档大于 0 才能启用。

例：档位是 **100 本站积分**，能量价格设为 **20**，用户成功支付后得到 100 积分。美元价格与这里的能量价格各自独立。

勾选启用并保存。重新读取页面确认商户、开关和售价保留正确，再去用户充值页面查看 NodeLoc 入口。

## 6. 通知与返回地址

程序建单时自动携带这两个地址，无需修改业务代码。若平台应用配置要求登记地址，复制自己后台显示的地址：

```text
通知： https://你的邮箱域名/api/payment/nodeloc-notify
返回： https://你的邮箱域名/api/payment/nodeloc-return
```

以演示站为例，通知路径是 `https://nodemail.513399.xyz/api/payment/nodeloc-notify`。**自己部署不能使用演示站的回调地址。**

通知请求需要能到达本站，不应被网站基础认证、浏览器挑战或缓存拦截。手动打开通知地址而没有合法支付参数，收到错误是正常的，不能据此判断通知接口坏了。

## 7. 对照当前接口实现

这部分用于核对接入平台，不需要手工调用接口付款。

| 项目 | 当前代码使用的值 |
| --- | --- |
| 网关 | `https://www.nodeloc.com`，代码固定 |
| 建单 | `POST /payment/api/pay/create` |
| 查询 | `POST /payment/api/pay/query` |
| 请求格式 | 表单 `application/x-www-form-urlencoded` |
| 签名 | `sign_type=RSA`，RSA-SHA256 |
| 支付类型 | `type=nodeloc` |
| 跳转方式 | `method=jump` |
| 本站订单号 | `out_trade_no` |
| 通知 / 返回 | `notify_url` / `return_url` |

本站会验证平台成功响应及通知签名，并核对订单资料。不能把网关改成任意一家易支付后，继续沿用同一组凭据。

## 8. 完成一笔验收

由站点所有者安排测试，平台支持测试环境时先用测试环境。没有测试环境时，确认金额后再用自己的账号做一笔小额订单。

检查四处：用户端建单和跳转正常；平台显示付款成功；本站订单变为已支付；积分流水只增加一次。返回页面、刷新和查询同一订单，都不应再次增加积分。

保存失败或超时，先刷新配置页核对结果，不要连续提交。已付款但未到账，查询原订单并检查平台通知记录，不让用户重复付款。

## 常见错误对照

| 提示或现象 | 优先核对 |
| --- | --- |
| 商户不存在 | PID 是否来自同一个已审批的支付应用 |
| 请求签名验证失败 | 本站私钥与平台登记的商户公钥是否配对 |
| 平台响应签名失败 | 本站“平台公钥”是否填对、平台是否换过公钥 |
| 时间戳无效或过期 | 服务器时间同步是否正常 |
| 不出现 NodeLoc 支付 | 开关、充值档位以及该档位能量价格是否大于 0 |
| 付款金额差很多 | 平台应用汇率是否确实设置为 1 |
| 已付款但没有积分 | 原订单状态、平台通知投递结果和本站核验日志 |
