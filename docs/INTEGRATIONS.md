# 第三方账号接入

支付商户、充值档位、回调地址与到账排查，请看独立的 [支付与充值配置](PAYMENTS.md)。

这些功能都可以等基本收信正常后再接。安装包不提供作者的应用、机器人或支付商户，也不会因为用了同一份源码就共用作者的账户。

## NodeLoc 登录和绑定

在后台 **系统配置 → NodeLoc 登录** 中填写自己的 Client ID、Client Secret 和用户端网站地址。把后台显示的完整回调地址复制到 NodeLoc 应用的 Redirect URI，域名和路径必须一致。

应用权限和审核按 NodeLoc 当时的要求完成，再开启登录入口。当前项目的接入说明见后台；官方入口是 [NodeLoc 文档](https://docs.nodeloc.com/api-reference/introduction)。

首次通过 NodeLoc 登录可以创建本站账户。已有本站账户应先用原方式登录，再到用户中心绑定，保留原账户的积分和邮箱。同邮箱不代表系统会自动合并两个账户。

社区等级来自最近一次 NodeLoc 授权，可能不是此刻的最新等级；用户可以通过更新社区资料重新同步。解绑需要验证本站密码，没有设置密码的账户应先完成本站密码设置。

不要把本站会员等级和 NodeLoc 社区等级混为一谈，它们不是同一项权益。

## Telegram 绑定

在系统配置的 Telegram 绑定页填入自己机器人的资料，按后台说明完成配置。用户随后在个人中心走绑定流程。

**当前仅完成账号绑定，暂不推送邮件或通知，也不能用于登录。** 如果用户绑定后没有收到邮件提醒，这属于当前功能范围，不是需要重新配置机器人。

机器人 Token 和回调相关密钥只保存在自己的后台，不要加入源码或公开文档。

## 支付与积分

先在自己的服务商处取得商户信息，再按后台字段填写。核对商户属于自己、回调地址指向自己的网站、币种和价格符合自己的设置。

USDT 网关需要在安装目录 `.env` 显式配置自己的 `NODEMAIL_GMPAY_ORIGIN`，填 HTTPS 根地址，再按安装流程启动应用并填写后台商户凭据。留空时不能启用这个网关。相关参数见 [安装指南](../installer/README.md)。

已经产生订单后，不要只改网关域名就切换支付平台，旧订单的查询和通知仍需要正确处理。切换需单独安排旧订单的处置。

### 怎样验收？

先确认服务商是否提供测试环境；使用测试环境核对下单、取消、通知和本站订单状态。只有账户所有者确认后再安排真实小额测试。网页跳回成功页不等于服务端已经确认付款。

订单、积分流水与业务防重复记录共同承担业务核对。不要清表测试重复回调，也不要手工把订单改成已支付来代替完整验收。

## 密钥更换前先备份

安装时生成的 `GUEST_SESSION_SECRET` 还用于保护多类服务凭据。它不是可以随手换掉的临时密码；更换或丢失后，原有加密资料可能无法读取。

请保留原 `.env`，按 [备份说明](BACKUP.md) 与数据库一起保存。服务商主动轮换凭据时，更新对应后台字段即可，不要重新生成整份安装配置。
