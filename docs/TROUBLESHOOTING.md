# 问题排查

先记下出错时间、刚执行的步骤和完整错误。不要一看到报错就重装；数据库和密钥一旦被覆盖，原本的小问题可能变成恢复问题。

## 构建时下载失败

先看错误出在基础镜像拉取还是 npm 依赖下载。检查服务器网络、DNS 和剩余磁盘。重试构建不会要求删除数据库，也不需要把支付密钥写进 Dockerfile。

`Cannot find Dockerfile` 通常是目录不对。进入真正包含 `Dockerfile` 的源码目录再构建，ZIP 解压后可能多套了一层文件夹。

## 找不到 node 或 docker

在服务器主机终端执行 `node --version` 和 `docker info`。如果在容器终端操作，先退出到主机；如果命令不存在，回到 [准备环境](PREPARATION.md)。Docker 提示权限错误时检查当前用户，不要给项目文件统一改成 777。

## configure 提示 .env 已存在

这是为了保留已生成的数据库密码和主密钥。确认是不是已经完成配置，如果是，继续初始化或启动对应步骤。不要删除 `.env` 再生成。

如果是旧站更新，应使用 [更新流程](UPGRADING.md)，不能重新初始化。

## 初始化提示数据库不为空

安装工具只接受完全空的新库。可能选中了已有安装，也可能上一次初始化中断留下了部分表。先看安装目录和具体错误，不要清库绕过检查。

全新测试安装可以另建隔离目录与独立配置重新验收；有业务数据的环境应先保存现场，按恢复流程处理。

## 网页显示 502

先在服务器终端执行：

```bash
curl --fail http://127.0.0.1:4321/api/health
```

如果这里也失败，查看 1Panel 中 app、db 容器的状态与日志，优先处理程序没有启动、数据库异常或端口冲突。

如果这里正常，再查网站代理地址、端口，以及 OpenResty 的网络模式。OpenResty 在 bridge 网络中时，它的 `127.0.0.1` 不是服务器主机；不能照搬 host 网络的代理地址。详见 [1Panel 教程](1PANEL.md)。

不要把应用端口开放到公网来掩盖代理连接问题。

## 网页显示 421

请求的域名必须与 `NODEMAIL_SITE_ORIGIN` 或相应允许配置一致。反向代理的 Host、X-Forwarded-Host 应保持用户访问的网站域名，不能一个填 localhost、另一个填公网域名。

核对是否误用了 IP、另一个子域名或旧域名访问。配置说明见 [安装参数与网络](../installer/README.md)。

## 登录后又回到登录页面

先确认浏览器使用 HTTPS、证书有效，代理设置 `X-Forwarded-Proto $scheme`，并关闭登录页面和 API 的缓存。检查是否从一个域名登录却跳到了另一个域名。

不要把关闭 Cookie 安全属性、移除来源检查当作修复方式。

## 网站正常，但收不到邮件

自有域名收信：核对收信域名、完整收件地址、MX 目标、mx 的 A 记录，以及入站 25。确认后台已添加对应域名，并且测试地址是当前有效的已申请邮箱。

中继收信：检查上游是否真的收到邮件、是否在垃圾箱、后台连接检测是否成功，随后看轮询日志。认证失败时去确认应用密码或 OAuth 授权，不要不停重试普通账户密码。

按 [收信教程](MAIL-GUIDE.md) 的两条路径分别检查，不要混用网站代理配置和 SMTP 配置。

## 用户被一起限流

检查反向代理是否覆盖 `X-Real-IP`。如果所有访问在应用看来都来自代理地址，会影响限流。用了 CDN 时，还需要先在代理上设置受信任的来源范围；不要信任任意客户端提交的 IP 头。

## 升级被拒绝

工具会核对数据库结构与原主密钥。迁移文件或摘要变化时，当前升级工具会停止，等待该版本的专门迁移说明。此时不应删除迁移记录、替换密钥或执行初始化。

健康检查失败后，升级工具会尝试恢复原镜像。如果恢复也失败，保留当前日志和旧镜像，检查容器，不要接着尝试其他版本。

## 提交问题时带哪些信息？

写清源码版本或提交号、系统与 CPU 架构、Docker/Compose/Node 版本、安装方式、错误发生步骤。附上相关日志片段和截图，遮住密钥、令牌、真实邮件内容及个人资料。

无需发送整份 `.env`、数据库导出或 SSH 私钥。文档里没有现成处理办法时，先保留现场比反复重装更有用。
