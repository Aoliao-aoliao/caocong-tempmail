# 支付与充值配置

**按你要接的渠道选择教程：**

- [NodeLoc 能量支付：应用、RSA 密钥、汇率、回调及验收](/payment-nodeloc)
- [USDT 支付：网关、PID、secret_key、接口格式及到账排查](/payment-usdt)

下面是渠道范围与价格单位速查。不要用另一种支付平台的商户信息混填。

这篇针对 **草丛临时邮箱 临时邮箱项目**。后台入口是 **充值配置**（`/admin/commerce.cgi`），里面有“NodeLoc 支付”“USDT 支付”“充值档位”“其他渠道”四个分区。它和另一个“草丛 Mail”站点的支付设置不是一套。

## 先看目前接通了哪些渠道

| 渠道 | 当前实现 | 用户付的是什么 |
| --- | --- | --- |
| NodeLoc 支付 | 支持建单、验签和核验后自动入账 | NodeLoc 能量，换取本站积分 |
| GM Pay / EPUSDT v2 | 支持 USDT / TRC20 建单、收银台、核验与入账 | TRON 网络的 USDT |
| 其他渠道中的支付宝、微信、其他加密网络 | 当前只是渠道展示配置，未接通这些平台的在线支付 | 不能靠勾选开关获得真实付款链接 |

商户号是某个平台分配给你的身份，不同平台之间不会自动共用。不要把已有易支付的 PID 或密钥直接填进另一种网关。界面出现“易支付 pid”，也不表示所有易支付平台和协议版本都能替换使用。

## 第一步：设置充值档位

打开 **充值配置 → 充值档位**。每一档分别填写积分、美元价格，并启用、保存。

| 字段 | 填写含义 | 例子 |
| --- | --- | --- |
| 积分 | 成功支付后发给用户的本站积分 | 100 表示发放 100 积分 |
| 美分 | 美元价格，单位是 cent | 100 表示 1.00 USD，120 表示 1.20 USD |
| 启用 | 是否出售这一档 | 开启后仍需有已接通的支付渠道 |

上面的数字只用于说明单位，不是推荐售价。改完一档要保存该档。NodeLoc 能量价格在它自己的支付分区单独设置，不会随美元价格自动换算。

## 方式一：NodeLoc 能量支付

### 准备商户信息

使用自己的 NodeLoc 支付应用，按服务商要求完成审批。后台提供 [NodeLoc 支付应用入口](https://www.nodeloc.com/payment/applications)。此处配置支付应用，与系统配置中的“NodeLoc 登录”不是同一套字段。

打开 **充值配置 → NodeLoc 支付**，用超级管理员填写：

| 后台字段 | 怎么填 |
| --- | --- |
| 商户 ID（易支付 pid） | 自己的 NodeLoc 支付应用的数字商户 ID |
| 本站 HTTPS 根地址 | 例如 `https://mail.example.com`，不带 `/admin/` 等路径 |
| 商户 RSA 私钥 | 此支付应用对应的商户私钥；配套商户公钥应登记在同一个应用 |
| NodeLoc 平台 RSA 公钥 | 平台提供的验签公钥，不能填成商户自己的公钥 |
| 汇率确认 | 按当前接入要求，在应用设置 `1 单位货币 = 1 能量`，确认实际修改后再勾选 |

NodeLoc 网关在程序中固定，不能在这里替换成另一家易支付地址。更换商户 ID 时必须同时填写它配套的私钥；同一商户留空私钥表示保留原值。

### 填能量价格，再启用

给需要出售的充值档位设置整数能量价格，填 `0` 表示这一档不通过 NodeLoc 出售。至少一档大于 0 才能开启。

例如某档发放 100 本站积分，你把能量价格设为 20，则这一渠道请求用户支付 20 NodeLoc 能量。它不是 20 美元，也不是 20 USDT。

保存配置后，重新打开页面确认保存结果。刷新后私钥不回显是正常设计，不代表保存失败。

### 回调地址

后台会根据本站地址显示付款通知地址。以自己的后台显示值为准：

```text
到账通知：https://mail.example.com/api/payment/nodeloc-notify
付款返回：https://mail.example.com/api/payment/nodeloc-return
```

支付通知是平台与本站服务器之间的请求；付款返回是用户浏览器回到本站。不要把后台登录地址当成通知地址。通知接口需允许平台正常访问，不应被网站登录认证、验证码挑战或缓存拦截。

## 方式二：USDT / TRC20 支付

### 先配置自己的网关地址

在原安装目录的 `installer/.env` 中找到 `NODEMAIL_GMPAY_ORIGIN`，填写你自己的兼容 GM Pay / EPUSDT v2 的网关根地址。例如：

```dotenv
NODEMAIL_GMPAY_ORIGIN=https://pay.example.com
```

这是示例，必须换成自己的实际地址。不要填写钱包收款地址，也不要加 `/submit.php` 或后台路径。该接入使用 GM Pay / EPUSDT v2 的接口，不能仅凭某个平台叫“易支付”就判断兼容。

保存 `.env` 后，在原 `installer` 目录运行：

```bash
node manage.mjs start
```

这是应用配置变更，会更新运行中的容器。不要重新执行 `configure` 或 `init`，也不要改变原主密钥。`.env` 中留空网关地址时，这条支付渠道无法启用。

### 填写后台凭据

打开 **充值配置 → USDT 支付**，用超级管理员填写：

| 字段 | 怎么填 |
| --- | --- |
| 商户 PID | 此 GM Pay / EPUSDT 网关分配的商户标识 |
| API 密钥 secret_key | 同一商户的 API 密钥，不是钱包私钥，也不是 NodeLoc 的 RSA 私钥 |
| 启用 USDT 支付 | 凭据和网关准备好后开启并保存 |

更换 PID 需要同时填写对应密钥。同一商户留空密钥会保留已保存值。保存后应看到网关地址、TRON 主网及配置状态。

### 回调和实际付款金额

展开 **回调地址与支付说明**，核对自己的地址：

```text
到账通知：https://mail.example.com/api/payment/gmpay-notify
付款返回：https://mail.example.com/api/payment/gmpay-return
```

充值档位以 USD 标价，实际要求支付的 USDT 数量由网关返回。让用户以收银台显示的**网络、收款地址、准确金额和有效期**为准，不要自行四舍五入或套用上一次订单的地址与金额。

当前这条接入只有 **USDT / TRC20（TRON）**。钱包支持多链，不代表这条支付接口已支持多链；不能通过改菜单名字把它变成 ERC20、BSC 或 Polygon。

本站收到通知后，会校验签名及订单、金额、资产和交易信息，核验通过才发积分。重复通知不会按每次通知重复发积分。浏览器跳回成功页面，也不能替代服务端核验。

## 为什么勾了渠道，前端还是不能付？

先看下面几处，不要一开始就更换商户号：

1. 充值档位是否启用并保存。
2. 对应的专用支付分区是否已配置凭据并开启。
3. NodeLoc 对应档位的能量价格是否大于 0。
4. USDT 的网关环境变量是否填写，应用是否已经重新启动读取。
5. 是否误把“其他渠道”的展示开关当成商户接入。

“其他渠道”里当前没有通用易支付网关配置。支付宝、微信或更多链的自动收款需要另做接口接入，不是补一个标签即可使用。

## 怎样检查到账流程？

先核对商户与域名归属，服务商有测试环境时优先在测试环境验收。没有测试环境时，由站点所有者安排一笔自己认可的小额订单，不要用真实用户订单试错。

依次确认：订单生成、跳转地址正确、付款后本站订单变为已支付、积分只增加一次、流水与订单一致。退出再登录，积分仍应保持正确。过期、取消或未付款订单不应发放积分。

在用户的充值记录查看订单，管理员通过 **充值订单** 和 **积分流水** 核对。USDT/NodeLoc 订单走网关核验流程，不要直接改数据库为已支付，也不要通过删业务防重复记录测试重放。

## 已付款但没到账

先保存本站订单号、网关交易号与时间。USDT 还可记录链上交易哈希；不要让用户重复转账。

检查网关是否已确认付款、通知是否发出、本站回调是否被代理或验证页拦截，再核对金额、网络与商户是否匹配。用户页面提供查询到账入口时，查询原订单，不重新创建订单代替排查。

## 密钥和升级

凭据在后端加密保存，不回显原密钥。请连同数据库保留原 `.env`，尤其是 `GUEST_SESSION_SECRET`，详见 [备份自己的数据](/backup.html)。

旧订单未处理完时不要随意更换支付网关。更换平台、商户或密钥前，先核对未结算订单和旧通知的处理方式。

本文按当前临时邮箱代码核对。写文档及发布文档不涉及真实付款、商户变更或生产配置修改。
